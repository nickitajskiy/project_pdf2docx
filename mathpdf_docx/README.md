# Математический PDF → Word

Учебное локальное приложение на Python 3.11/3.12 с русским интерфейсом Streamlit. Основная область применения: одноколоночные русские учебные PDF с текстовым слоем. Ни точное совпадение вёрстки, ни полнота обнаружения формул, ни математическая правильность OCR не гарантируются. Авторское содержание и опечатки не исправляются.

## Установка Windows

Установите Python 3.11 (64 bit), отметьте «Add Python to PATH». Распакуйте проект и откройте терминал в его папке:

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python run.py
```

После установки можно запускать `start.bat`. Активация окружения и изменение политики PowerShell не нужны.

## Установка macOS

Установите Python 3.11, например `brew install python@3.11`. В терминале перейдите в папку проекта (пути с пробелами заключайте в кавычки):

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py
```

После установки доступен `start.command` (если необходимо, `chmod +x start.command`). Приложение открывается по адресу http://127.0.0.1:8501. Для завершения нажмите Ctrl+C в терминале.

## Три режима

1. **Редактируемый текст, формулы изображениями**. Требуется дополнительная модель MFD Pix2Text. Текст извлекается из PDF, формулы вырезаются из рендера 216 dpi. Внутри абзаца формула остаётся отдельным изображением с физическим размером, близким к оригиналу; высокие формулы располагаются отдельно. Символы заменённой области удаляются из текстового представления. Формулы не редактируются как математика Word.
2. **Редактируемые формулы**. Дополнительно нужны MFR и Pandoc. Формулы локально распознаются в LaTeX, Pandoc создаёт OMML. Любая ошибка OCR или преобразования даёт исходную вырезку и предупреждение. Каждый результат OCR считается непроверенным: наличие OMML не доказывает правильность формулы. При отсутствии Pandoc весь режим продолжает работать с формулами изображениями и явно учитывает замены в отчёте. При недоступном MFD обработка прекращается с инструкцией, доступен режим 3.
3. **Сохранить внешний вид**. Работает на базовых зависимостях, вставляет по одной странице PDF на страницу DOCX. Текст и формулы не редактируются. Рекомендуется для сканов, колонок, таблиц, рисунков и непроверенной сложной вёрстки.

Для совместимости с Pandoc эквивалентно нормализуются команды оформления дробей (`\cfrac`, `\dfrac`, `\tfrac`), отдельные записи корней, каллиграфических букв и пределов интегралов. Пустые строки оформления OCR снимаются; неполные матрицы и индексы без основания отклоняются с резервной заменой. Исходный LaTeX и применённые изменения доступны в отчёте. Математические значения и сомнительные символы автоматически не исправляются. Интерфейс отдельно показывает количество OMML и резервных изображений.

Основной режим никогда автоматически не превращает документ в набор полных изображений страниц.

## Математические зависимости и модели

Это отдельная, существенно более тяжёлая установка. Не устанавливайте дополнительные системы распознавания.

```sh
# macOS; на Windows замените .venv/bin/python на .venv\Scripts\python
.venv/bin/python -m pip install -r requirements-math.txt
.venv/bin/python -m mathpdf doctor --load-models
# Дополнительно загрузить MFR для распознавания:
.venv/bin/python -m mathpdf doctor --load-models --recognition
```

Ревизии открытых весов зафиксированы в `mathpdf/math_engine.py`, чтобы обновление репозитория не меняло модель незаметно.

Первый запуск требует интернета для получения открытых моделей **mfd-1.5** и **mfr-1.5**. Необходимые объём диска/память зависят от платформы; распознавание на CPU может быть медленным. Используется только локальный API моделей; облачные VLM и платные варианты не подключаются. PDF и вырезки не отправляются внешним сервисам. Streamlit telemetry отключена.

Каталог моделей по умолчанию `models` в текущей папке. `MATHPDF_MODEL_DIR` задаёт другой каталог. Для уже полученных файлов можно задать `MATHPDF_MFD_PATH` (файл ONNX MFD) и `MATHPDF_MFR_DIR` (каталог модели MFR с конфигурацией и токенизатором). После подготовки весов обработка локальна; для строгой автономности задайте эти пути и `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`. Команда doctor без `--load-models` не скачивает и не загружает модели. Она отличает наличие пакета от проверенного запуска весов.

Веса загружаются через Python API huggingface_hub без shell-команд; используются явные пути к локальным файлам.

Зафиксированы Pix2Text 1.1.4 и совместимые Transformers 4.48.3 / Optimum 1.24.0: Optimum 1.24 требует Transformers <4.49 для ONNX. MFD и MFR создаются отдельно, поэтому не загружаются модели OCR русского текста, таблиц и анализа макета. Применены реальные API `MathFormulaDetector(...)(image, resized_shape=1536)` и `LatexOCR.recognize(...)`. Результаты испытаний именно этого окружения находятся в `VALIDATION.md`.

## Pandoc

Проверка: `pandoc --version`. Установите Pandoc с https://pandoc.org/installing.html (macOS: `brew install pandoc`; Windows: установщик или `winget install --id JohnMacFarlane.Pandoc`). После установки перезапустите терминал и приложение, чтобы обновился PATH. Pandoc вызывается без shell, с тайм-аутом 30 секунд. Неподдерживаемый LaTeX, диагностические сообщения и отсутствие математических элементов вызывают резервную замену изображением.

## Диагностика и командная строка

```sh
.venv/bin/python -m mathpdf doctor
.venv/bin/python -m mathpdf convert "2023_fan.pdf" "результат.docx" --mode images
.venv/bin/python -m mathpdf convert "2023_fan.pdf" "проверка.docx" --mode images --pages 1,2,5,8
.venv/bin/python -m mathpdf convert "2023_fan.pdf" "страницы.docx" --mode pages
.venv/bin/python -m mathpdf convert "2023_fan.pdf" "формулы.docx" --mode omml
```

Рядом с DOCX сохраняются `.report.txt` и `.report.json`. Интерфейс предлагает скачать эти же результаты. JSON содержит промежуточные блоки с исходной страницей, координатами в пунктах PDF (начало сверху слева), типом, текстом/LaTeX, именем вырезки, способом обработки и предупреждениями. Имена вырезок — идентификаторы: сами временные изображения удаляются после сборки DOCX; встроенные изображения находятся в архиве DOCX `word/media`.

Настройка ограничений: `MATHPDF_MAX_MB` (по умолчанию 50) и `MATHPDF_MAX_PAGES` (100). Для лимита интерфейса Streamlit также измените `server.maxUploadSize` в `.streamlit/config.toml`. CLI принимает `--max-mb` и `--max-pages`. Один рендер страницы ограничен размером PDF до 3000 пунктов на сторону. Источник не изменяется; для каждого запуска создаётся отдельный временный каталог.

## Тесты

```sh
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

Проверенное окружение поставки: macOS 27 ARM64, Python 3.12.14. Синтаксис также проверен Python 3.11; полный прогон зависимостей на Python 3.11 и Windows не выполнялся. Математический набор с Torch 2.6 рассчитан на платформы, для которых доступны его wheels (современные Windows x64 и macOS Apple Silicon); macOS Intel этим набором не проверялся.

Тесты используют системный Arial или DejaVu Sans для русского текста. Проверяются текст, верхний ноль, inline и отдельная формулы, отсутствие дублирования, резервные замены, OMML с дробью, недоступная модель, повреждённый/пустой/зашифрованный PDF, скан, ограничения, неизменность источника. Детерминированный тестовый детектор задаёт известные области синтетического документа и **не является проверкой качества Pix2Text**. Тест OMML запускает настоящий установленный Pandoc; при отсутствии он пропускается с указанием причины.

## Архитектура

- `pdfio.py`: проверка PDF, pdfplumber и рендер pypdfium2.
- `math_engine.py`: локальные MFD/MFR Pix2Text, повторное использование моделей и блокировка доступа между сессиями.
- `layout.py`: границы областей по детектору и белым промежуткам строк списка, объединение существенных пересечений, порядок строк, верхние отметки, отступы и приближённое объединение строк в абзацы.
- `omml.py`: изолированный безопасный запуск Pandoc и проверка математической разметки.
- `writer.py`: DOCX с редактируемыми фрагментами, изображениями и OMML.
- `converter.py`: последовательность этапов и временные файлы; `schema.py`: промежуточные блоки и отчёт.
- `app.py`: Streamlit; результат хранится в сессии, загрузки и переключения элементов интерфейса не запускают конвертацию. Модели кешируются на процесс, каждый документ анализируется только по нажатию кнопки.

## Ограничения

Детектор способен пропустить формулу или неправильно очертить её. Есть дополнительные области по неопознанным Unicode и математическим знакам, но это не гарантия обнаружения всех формул. Их использование отмечается в отчёте. Только курсив или имя шрифта не являются основанием для замены области.

Восстановление абзацев, заголовков, номеров задач и буквенных пунктов геометрическое. Нумерация сохраняется текстом, включая верхние отметки, а не автоматическим списком Word. Автоматическое удаление дефисов отключено, поскольку оно может менять выражения и авторское написание. Порядок страниц и продолжений сохраняется; абзацы на разных страницах могут остаться отдельными. Исходные номера страниц отмечаются отдельно в JSON, в DOCX используется собственная нумерация.

Сложные колонки и таблицы поддерживаются только в режиме страниц; диагностика колонок эвристическая. Растровые рисунки сохраняются. Отдельные векторные рисунки требуют ручной проверки; наличие контуров отмечается с номером страницы, внутри вырезок формул контуры сохраняются. Неизвестные блоки не объявляются корректно распознанными. Для полной сохранности внешнего вида используйте режим страниц. В проверенном образце исправлены выпадавшие скобки нижних пределов интегралов; геометрическое дополнение рамки не удаляет знаки из документа. На других PDF границы областей требуют проверки.

Для OCR нельзя интерпретировать модельный score как вероятность математической правильности. В отчёте нет придуманных процентов точности. Перед использованием учебного материала сверяйте каждую формулу с PDF, особенно индексы, пределы, корни, вложенные дроби, кусочные функции и скобки.
