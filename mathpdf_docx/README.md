# Математический PDF → Word — Tkinter

Обычное настольное приложение Python с русским окном **Tkinter**. Браузер, localhost, сервер и аккаунты не нужны. Откройте проект в PyCharm или VS Code, выберите окружение и запустите `run.py`. Из корня GitHub-репозитория можно запускать `main.py`.

Основная область применения — одноколоночные русские учебные PDF с текстовым слоем. Точная вёрстка, полнота обнаружения формул и математическая правильность OCR не гарантируются. Авторское содержание и опечатки не исправляются.

## Быстрый запуск для преподавателя

Скачайте GitHub → Code → Download ZIP, распакуйте. Команды ниже выполняются **в папке `mathpdf_docx`**, где находятся `run.py` и зависимости. Рекомендуется обычный Python **3.11, 64 bit** с сайта https://www.python.org/downloads/ с установленным Tcl/Tk. Код также проверялся на Python 3.12.

### Windows

При установке Python включите `pip`, `tcl/tk and IDLE`, `Add Python to PATH`.

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python run.py
```

После установки можно запускать `start.bat`. Активация окружения и изменение политики PowerShell не требуются.

### macOS

Установщик Python с python.org включает Tcl/Tk. Если используете Python из Homebrew, пакет Tk нужно установить отдельно для той же версии Python (например, `brew install python@3.11 python-tk@3.11`).

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py
```

После установки доступен `start.command` (если необходимо: `chmod +x start.command`).

**Базовая установка уже позволяет открыть окно и конвертировать PDF режимом «Сохранить внешний вид».** Для редактируемого текста и формул установите дополнения ниже.

## Запуск в IDE

1. Откройте распакованный репозиторий или папку `mathpdf_docx` в PyCharm / VS Code.
2. Выберите интерпретатор созданного `.venv`: `.venv/Scripts/python.exe` на Windows или `.venv/bin/python` на macOS. Если открыт корень репозитория — окружение находится в `mathpdf_docx/.venv`.
3. Выполните установку зависимостей этим интерпретатором.
4. Нажмите Run для корневого `main.py` либо `mathpdf_docx/run.py`. `app.py` также открывает то же окно.

Запуск не зависит от рабочей директории IDE. Модели по умолчанию хранятся в `mathpdf_docx/models`, рядом с исходниками, а не в произвольной папке IDE.

## Редактируемый текст и формулы

Дополнительные математические пакеты крупные. Установите их один раз в то же окружение:

```sh
# Windows: вместо .venv/bin/python используйте .venv\Scripts\python
.venv/bin/python -m pip install -r requirements-math.txt
.venv/bin/python -m mathpdf doctor --load-models
.venv/bin/python -m mathpdf doctor --load-models --recognition
```

Для формул Word отдельно установите **Pandoc**: https://pandoc.org/installing.html . На macOS — `brew install pandoc`, на Windows — официальный установщик. Перезапустите IDE после установки, чтобы обновился PATH. Проверка: `pandoc --version`.

Первое скачивание открытых моделей `mfd-1.5` и `mfr-1.5` требует интернета; после получения весов обработка локальная. API-ключи, регистрация и платные сервисы не нужны. PDF и вырезки не передаются внешним сервисам. Веса и виртуальное окружение не включены в GitHub/ZIP.

Pix2Text 1.1.4, Transformers 4.48.3 и Optimum 1.24.0 зафиксированы совместно. Модели вызываются напрямую через `MathFormulaDetector` и `LatexOCR.recognize`; дополнительные системы OCR не устанавливаются для сравнения. Ревизии весов закреплены в `mathpdf/math_engine.py`. Подробности — [MATH_SETUP.md](MATH_SETUP.md).

Проверенный математический runtime: macOS ARM64 / Python 3.12.14, CPU. Полный прогон Windows, Python 3.11 и macOS Intel не выполнялся. У зафиксированного Torch 2.6 могут отсутствовать wheels для macOS Intel: запуск окна и режим страниц проверяйте отдельно от математического набора. Наличие исходников для двух ОС не означает проведённого испытания обеих ОС.

## Как пользоваться

1. Нажмите «Выбрать PDF…» или вставьте путь к файлу.
2. Выберите режим и нажмите «Конвертировать».
3. Дождитесь завершения. Этап и прогресс отображаются в окне; распознавание выполняется в фоновом потоке.
4. Просмотрите отчёт и нажмите «Сохранить DOCX и отчёты…».
5. Выберите папку. Рядом с DOCX сохранятся `.report.txt` и `.report.json`. Отмена диалога не теряет готовый результат; можно сохранить его позже.

Пока выполняется конвертация, параметры заблокированы. Закрытие окна просит дождаться завершения. Загрузка моделей не запускается при открытии окна или переключении режима.

| Режим | Результат | Что необходимо |
|---|---|---|
| Редактируемый текст, формулы изображениями | Текст редактируется, математические вырезки — изображения 216 dpi | База + MFD |
| Редактируемые формулы | OMML — формулы Word; ошибки преобразования сохраняются изображениями и учитываются в отчёте | База + MFD/MFR + Pandoc |
| Сохранить внешний вид | Каждая страница — изображение, текст и формулы не редактируются | Только база |

При отсутствии модели показывается причина и инструкция; можно выбрать режим страниц. При отсутствии Pandoc формулы сохраняются изображениями с предупреждениями. Наличие OMML не доказывает математическую правильность: сверяйте формулы с оригиналом.

Для совместимости с Pandoc эквивалентно нормализуются команды оформления дробей, отдельные записи корней, букв и пределов. Сырой LaTeX и изменения записываются в отчёт. Неполные структуры отклоняются. Для простых однострочных записей допускается узкий резерв из Unicode и геометрии индексов PDF (`textmath.py`); неизвестные глифы и сложные конструкции не угадываются.

## Диагностика

```sh
.venv/bin/python -m tkinter
.venv/bin/python -m mathpdf doctor
```

Первая команда должна открыть тестовое окно Tcl/Tk. Если отсутствует `_tkinter`, `pip install tkinter` не поможет: нужен Python с Tcl/Tk. Если окно не открывается, проверьте, что запуск выполняется в обычной графической сессии, а не на сервере без экрана.

Если IDE сообщает, что пакет не найден, выберите правильный `.venv` и установите зависимости в нём. Для `PermissionError` при сохранении закройте DOCX в Word и выберите доступную папку. При недоступных моделях проверьте `requirements-math.txt`, интернет первого запуска и диагностику `--load-models`.

Лимиты: `MATHPDF_MAX_MB` (50 по умолчанию) и `MATHPDF_MAX_PAGES` (100). Задайте их в переменных окружения IDE перед запуском. Каталог моделей можно изменить через `MATHPDF_MODEL_DIR`, конкретные файлы — через `MATHPDF_MFD_PATH` / `MATHPDF_MFR_DIR`. Для автономного запуска подготовленных моделей: `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`.

## Командная строка и тесты

```sh
.venv/bin/python -m mathpdf convert "2023_fan.pdf" "результат.docx" --mode images
.venv/bin/python -m mathpdf convert "2023_fan.pdf" "формулы.docx" --mode omml
.venv/bin/python -m mathpdf convert "2023_fan.pdf" "страницы.docx" --mode pages
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

Тесты окна требуют доступного Tk и графической сессии. В окружении без экрана они пропускаются с объяснением; остальные проверки конвейера работают без окна. Тесты OMML требуют реального Pandoc; без него пропускаются с объяснением.

## Архитектура и ограничения

- `run.py` / корневой `main.py`: запуск окна из IDE и настройка каталога моделей.
- `mathpdf/desktop.py`: Tkinter/ttk, диалоги выбора и сохранения, фоновая конвертация, очередь событий. Вызовы Tk выполняются только в главном потоке.
- `converter.py`, `pdfio.py`: проверка PDF, pdfplumber, рендер pypdfium2, отдельный временный каталог для каждой задачи.
- `layout.py`: координаты блоков, порядок чтения, пробелы, верхние отметки и приближённые абзацы.
- `math_engine.py`: локальные MFD/MFR, повторное использование моделей на процесс.
- `omml.py`, `textmath.py`: Pandoc с тайм-аутом и узкий резерв простых записей из PDF.
- `writer.py`, `schema.py`: DOCX и отчёт с исходными страницами, рамками, способом обработки и предупреждениями.

Источник не изменяется. Пути с пробелами и кириллицей поддерживаются. Сканы, колонки, таблицы и непроверенные рисунки рекомендуется сохранять режимом страниц; диагностика сложного макета эвристическая. Переносы и отступы восстанавливаются приближённо. Математическая правильность OCR не гарантируется; счётчики не являются процентом точности. Конвертер и ранее подготовленные примеры сохранены при замене интерфейса.
